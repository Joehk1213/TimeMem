# TimeMem PWA 介面設計與驗收

## 目的與適用範圍

為 TimeMem PWA 做介面工作時使用本 skill。成果要清晰、可信、容易操作、可直接使用，不能只交付靜態畫面或設計稿。

PWA 執行時只准由以下四個檔案組成：

- `index.html`：所有畫面標記、樣式及程式碼均放在此檔。
- `manifest.json`：安裝資訊。
- `sw.js`：服務工作者及離線快取。
- `icon.png`：應用程式圖示。

不可為樣式、程式、字體或元件新增檔案、套件、框架、建置流程或外部資源。除非任務明確要求，勿改動清單以外的檔案；不要擅自改動服務工作者、安裝資訊或圖示。只在 `index.html` 內完成 UI 的 HTML、CSS 及 JavaScript。

本 skill 是整合式工作流程，不要求同時啟用其他設計 skill，也不會取代實際操作與驗收。

桌面負責開發，Server 只負責運行。唔好喺 Server 度直接改，要喺 Desktop 度改，喺 Desktop 睇到順眼，先至再放去 Server。

## 工作準則

1. 先理解 TimeMem 的使用目的、現有介面、資料流程及使用情境，再決定視覺方向；不要只根據產品名稱猜功能。先睇而家個 `index.html`，講明邊度最唔開胃，唔好一嚟就寫 code。
2. 先有清楚的版面層級與互動理由，再寫程式。每個元件都要服務一項真實任務。
3. 優先採用語意正確的 HTML、原生瀏覽器能力與簡單可讀的程式結構。保留既有行為；不為了視覺效果改寫不相干的功能。
4. 所有顏色、文字、按鈕及資料都要有真實用途。不可留下假文案、假資料、空連結、無效按鈕或只做外觀的表單。
5. 不確定的需求要明確標示，不可把推測寫成已實作或已驗證的事實。
6. 設計品質不是驗收結果。未通過文末收貨閘門，不可聲稱完成。

## 視覺方向：有辨識度，但不賣弄

採用一個能呼應 TimeMem 實際用途的視覺概念，讓顏色、字體、資訊密度、留白及元件形狀前後一致。保持安靜、可靠、便於反覆使用的感覺；以閱讀與操作為主，不把工具介面做成宣傳頁。

### 風格三選一，開波前要問清楚

1. **乾淨簡約**：白底、少少圓角、大字、一個主色，睇落清爽
2. **暖紙風（TimeMem 預設）**：米色底、深灰字、暖主色，好似記事簿，啱記嘢
3. **深色現代**：深灰底、亮色按鈕，夜晚睇都舒服

未揀之前，預設用暖紙風。

避免未經理由套用以下做法：

- 紫藍漸層、發光球體、模糊背景、玻璃卡片等常見生成式樣板。
- 為了填滿畫面而加入英雄大標、裝飾插畫、徽章或不必要的卡片。
- 大量陰影、圓角、動畫，或把每個區塊都做成同一種卡片。
- 以顏色、圖示或動畫單獨表達狀態或操作。
- 看似精緻、實際難讀或難按的細字、淺色字及小型圖示按鈕。
- 千篇一律嘅 AI 樣：成版紫藍漸變、成版玻璃擬態、成版大 Emoji 做裝飾。

可用有節制的色彩、清晰字級、留白、排版對比及少量細節建立辨識度。每個裝飾效果都必須讓資訊更容易理解；否則清走。

## 設計系統：由品牌色推導整套規則

開始實作前，查看既有品牌色與介面。如無指定品牌色，根據產品既有介面選一個主色並說明依據，不要無故換色。再選一種整體風格，例如「沉靜編輯感」、「明亮實用」或「溫和紙本感」；不可只貼風格標籤，須把選擇落實到字體、色彩、間距、邊框與陰影。

先建立完整設計規則，再套用元件。所有自訂樣式變數均用中文名稱，不用英文變數名；以下係暖紙風例子，不是指定配色，實際交付時按既有風格調整數值：

```
:root {
  --品牌主色: #C96F2E;
  --品牌深色: #A85A22;
  --品牌淺色: #F5E3D0;
  --頁面底色: #FAF6EF;
  --卡片底色: #FFFFFF;
  --主要文字色: #1F1B16;
  --次要文字色: #6B645A;
  --邊框色: #E8DDCF;
  --錯誤色: #A52C2C;
  --成功色: #24633D;
  --鍵盤焦點色: #1256A0;
  --介面字體: system-ui, sans-serif;
  --正文大小: 1rem;
  --小字大小: 0.875rem;
  --標題大小: 1.375rem;
  --間距細: 0.25rem;
  --間距小: 0.5rem;
  --間距中: 1rem;
  --間距大: 1.5rem;
  --卡片圓角: 1rem;
  --小圓角: 0.625rem;
  --浮層陰影: 0 0.375rem 1.25rem rgb(31 27 22 / 8%);
}
```

實際交付時按既有風格調整數值，並為以下項目建立一套完整、一致的規則：

- **色板**：品牌主色及其深淺層級、中性色、頁面與卡片底色、邊框、文字、成功、提醒、錯誤及焦點顏色。狀態色亦須有足夠對比，並配合文字或圖示。
- **字體**：使用系統字體，避免網絡字體依賴；定義標題、正文、輔助文字、字重、行高及長字換行方式。
- **間距與尺寸**：以一致的間距級距處理容器、欄位、清單與卡片；互動區域的尺寸不可低於本 skill 的要求。
- **邊框與陰影**：統一邊框粗幼、圓角、分隔線及陰影層級；只在需要建立層次時使用陰影。
- **版面寬度**：至少檢查 320、較闊手機、平板及桌面寬度；把實際版面轉折點列為規格。CSS 媒體查詢使用明確尺寸，不要假設自訂屬性能放入媒體查詢。
- **動效**：只在有助理解狀態或回饋操作時使用，時間短、幅度小，並遵守減少動態效果設定。

顏色必須按實際文字與底色組合計算對比，不能只憑色票或肉眼估算。文字、圖示、焦點外框與元件狀態都要在實際呈現位置檢查。成個 PWA 只用上面嗰啲變數，唔好喺組件入面寫死色碼同字體。

## 元件規格

每個元件都要符合用途、語意、操作方式及狀態要求。使用原生 HTML 元素；不要以可點擊的普通區塊冒充控制項。每個組件都要有齊狀態，唔好淨係做 happy-path。

### 卡片

- 只在資訊需要分組或與背景區隔時使用卡片。
- 依內容選用適當的語意容器；標題層級正確，文字不截斷重要內容。
- 卡片本身不是按鈕。若整張卡片可操作，使用真正的連結或按鈕，並確保名稱能說明目的。
- 長內容、窄螢幕及文字放大時仍須自然換行。
- 白底、圓角、淺陰影、邊框用變數，內邊距最少 16px。

### 按鈕

- 有明確動詞或動作名稱；圖示按鈕必須有可辨識的無障礙名稱。
- 使用真正的按鈕或連結，依行為選擇元素。不可用空連結、無效網址或沒有事件的按鈕充數。
- 定義一般、滑過、按下、鍵盤焦點、停用及處理中狀態。停用或處理中時須避免重複送出，並讓使用者知道發生甚麼事。
- 可按範圍至少為 **44 × 44 CSS 像素**；圖示可以較小，但外層可按範圍仍要達標。
- 主按鈕：主色底、白字、圓角、撳落要有回應（變深 / 縮少少），唔好死掣。次按鈕：透明底、主色字、主色邊框。

### 輸入框與表單

- 每個輸入欄位均有可見標籤，不以提示文字代替標籤。
- 提供適合的輸入類型、必填或格式說明、清楚的驗證訊息及錯誤關聯。
- 輸入、提交、清除及取消等操作都必須實際運作；提交後要顯示明確結果。
- 錯誤不可只用顏色表示；要有可讀訊息，並把焦點或錯誤提示帶到合適位置。
- 輸入框：白底、邊框、focus 要有明顯外框，唔好淨係變色。

### 列表

- 使用符合內容關係的清單語意，項目順序、標題、日期或其他資料一目了然。
- 每列只把真正可操作的部分設為控制項，避免整列誤觸或多層互相巢狀的控制項。
- 有移除、編輯或其他動作時，明確指出該動作作用於哪一項；完成後提供可理解的回饋。
- 空清單、長清單及內容過長都要有合理呈現方式；不可用假項目填充畫面。
- 列表：一行一項，左邊標題，右邊時間 / 狀態，行與行要有分隔。

### 空白、載入與錯誤狀態

- **空白狀態**：說明目前沒有甚麼，以及使用者可以採取的下一步；沒有可行動作時，不要硬加按鈕。唔好留白，要講明點解空、同埋下一步撳邊度。
- **載入狀態**：只在工作進行中顯示；長時間工作應提供可理解的進度或狀態。避免以閃爍骨架屏代替真實結果。要講明載入緊，唔好成版空白。
- **錯誤狀態**：說明哪些操作失敗、資料是否保留，以及可否重試；提供真正可用的重試操作。要講明咩錯、同埋點再試，唔好淨係話「出錯」。
- 三種狀態必須對應實際資料流程，不可只以靜態文字或固定範例假裝已完成。

## 響應式、易用及無障礙要求

### 小螢幕與版面重排

- 在 **320 CSS 像素寬**下逐項檢查；頁面不得出現整頁橫向捲動、被切掉的控制項、互相重疊的文字或被遮住的操作。
- 內容應自然重排、換行，並容許瀏覽器放大文字；不要用固定寬度或裁切來掩蓋問題。
- 檢查直向與橫向、瀏覽器工具列及 iOS 電話安全區域；重要按鈕不可被瀏海、底部操作區或系統介面遮擋。
- 橫向捲動只可用於本身確實需要橫向瀏覽的內容，並須讓用途明確、可操作。

### 對比、標籤與焦點

- 一般大小文字的前景與背景對比至少 **4.5:1**；大型文字至少 **3:1**。提示文字、停用文字以外的資訊文字亦須清晰易讀。
- 不可移除瀏覽器焦點外框而沒有清楚可見的替代樣式；焦點須與周圍有足夠對比。
- 所有表單控制項、連結與按鈕均有可理解名稱；圖片若有資訊用途，提供合適替代文字，純裝飾圖片則避免造成多餘朗讀。
- 錯誤、選取、成功及警告不能只靠顏色傳達。
- 對照 **WCAG 2.2 AA** 檢查可感知性、操作性、可理解性及穩健性；不得宣稱只靠自動掃描已符合完整 WCAG。

### 鍵盤操作檢查

- 用「Tab 鍵」依序移到下一個可操作項目，用「Shift + Tab 鍵」移回上一個項目；焦點順序要跟畫面閱讀次序一致。
- 用「Enter 鍵」開啟連結或啟動相應操作；用「空白鍵」啟動按鈕。原生控制項應保留瀏覽器預設操作方式。
- 需要方向鍵操作的元件，須明確設計並實測方向鍵行為；不可令使用者猜測。
- 若有對話框或彈出層，開啟後焦點移入合適位置；按「Esc 鍵」可關閉，關閉後焦點回到開啟它的控制項。
- 全程不可困住焦點；每個可操作功能均須可用鍵盤完成，且焦點不可被固定工具列或浮層遮擋。

### 減少動態效果

- 所有動畫及平滑捲動均須尊重系統的「減少動態效果」偏好設定。
- 偏好減少動態效果時，移除非必要位移、視差、循環動畫及平滑捲動；仍需保留操作結果、狀態變化及必要回饋。
- 不得以 JavaScript 強制覆蓋使用者的系統偏好，也不可用無限動畫表示載入。

## 實作結構與效能

- 在 `index.html` 內維持清楚分區：文件資訊、內嵌樣式、語意化畫面標記及內嵌程式碼。
- CSS 以少量一致規則支援元件與狀態，避免多處重複覆寫、無用選擇器及只為單一裝飾增加大量程式碼。
- JavaScript 只處理必要互動；為事件監聽器、非同步操作、錯誤及重複提交設計明確行為。
- 頁面初次顯示要快，避免大型外部資源、重複繪製、過量陰影與大量監聽器；離線或網絡失敗時，不得令介面靜默卡死。
- 動效只做 `transform`、`opacity`、`filter`、裁剪呢啲，唔好做 `width` / `height` / `top` / `left` 動效。動效要輕，唔好成版一齊郁。
- 電話上面要減動效，唔好喺觸控部機度做重動效。用 `content-visibility: auto` 俾長列表。圖片要細，`icon.png` 唔好無限放大。
- 不要自行增加 React、Next.js、Tailwind、動畫函式庫、外部字體或其他依賴。不得把 marketing landing page 的技術選擇帶入 PWA。
- 唔好用 CDN、唔好外載任何嘢、唔好加新依賴、唔好加追蹤、廣告、外部叫用。
- 如任務涉及離線行為，先確認現有快取邏輯及更新策略，再判斷是否需要改 `sw.js`；本 skill 不授權擴大檔案或任務範圍。

## 參考方向的取捨

只吸收以下工作方法，並按 TimeMem 的四檔案限制重新組合；不得照抄其他 skill 的程式、品牌、文案或建置方式。

- **frontend-design**：採用可直接交付的元件品質與反制樣板化的設計思路，不把流行效果當成設計本身。
- **ui-design-system**：由品牌色與風格推導色板、字體、間距、陰影、版面轉折及對比規則；變數名稱用中文。
- **landing（行銷單檔）**：只在另有行銷頁需求時參考「單檔 HTML、樣式與程式同檔」及四種視覺方向：深色專業、清爽留白、活潑品牌、穩重企業。它不是 PWA 主介面的設計指令，亦不引入動畫函式庫。TimeMem PWA 本身就係單檔，所以單檔嗰個概念最啱參考。
- **design-qa**：驗收瀏覽器實際呈現及真實互動，不評主觀品味；死按鈕、假文案、缺少狀態、焦點、對比或窄版溢出均屬阻擋問題。
- **a11y-audit**：按 WCAG 2.2 概念檢查語意、鍵盤、標籤、狀態提示、對比與焦點；修正後重新驗證，不把掃描結果當成完整符合聲明。
- **senior-frontend**：只採納語意結構、程式簡潔及效能觀念；略過 React 起項目、套件、腳手架及框架專屬流程。
- **apple-hig-expert**：只在介面實際用於 iOS 電話端時，參考單手可達、系統安全區、文字易讀及觸控操作。不可把平板、桌面或其他平台的規則套到所有部機。
- **epic-design**：只可在工作開場用一句視覺方向啟發構想；不得把景深、視差、逐字動畫或電影式捲動效果套用到整個工具介面。
- **landing-page-generator**：只提煉清楚訊息層次及視覺選擇的概念；不可產生 Next.js、React 或 Tailwind 結構。

## 工作流程

1. **讀取現況**：檢查現有 `index.html` 的結構、樣式、事件、資料流及目前 PWA 行為。只讀取完成任務所需的範圍；不輸出或複製內網網址、Tailscale 位址、登入資料或其他秘密。
2. **定義範圍**：列出要支援的使用者任務、元件、互動及狀態。保留未被要求修改的現有功能。
3. **定義視覺系統**：選定一個品牌主色與一種整體風格，建立中文命名的設計變數，驗證重要文字與底色對比。問清楚用邊個風格，寫返個變數表俾 Joe 睇。
4. **實作完整狀態**：完成卡片、按鈕、輸入框、列表及適用的空白、載入、錯誤狀態；所有控制項均須有實際行為。
5. **檢查窄版與鍵盤**：至少測試 320 CSS 像素寬和桌面寬；以鍵盤走完所有操作，確認焦點順序、焦點可見及操作結果。
6. **實測與修正**：在瀏覽器檢查畫面、錯誤主控台、互動、對比、狀態及減少動態效果。每發現阻擋問題便修正並重測。
7. **核對範圍**：確認 PWA 執行資產仍限於四個指定檔案；不得順手更動服務設定或不相關檔案。
8. **回報證據**：只報告實際完成並驗證的項目。無法實測的項目須列作「未驗證」，不能算通過。

## 收貨閘門：未全過，不可宣稱完成

以下每項均須有實作或測試證據；任何一項未通過或未驗證，都不可回報「完成」或「已通過」。先修正阻擋項目，再從頭重測相關流程。

- [ ]  PWA 執行資產仍只有 `index.html`、`manifest.json`、`sw.js`、`icon.png`；未新增依賴、外部資源或建置步驟。
- [ ]  卡片、按鈕、輸入框及列表均存在於適用畫面，語意及用途清晰。
- [ ]  適用的空白、載入、錯誤狀態均已實作，且與真實資料及操作結果相連。
- [ ]  沒有死按鈕、空連結、假文案、假資料、無功能表單或未處理的使用者操作。
- [ ]  一般文字對比至少 **4.5:1**；大型文字至少 **3:1**；檢查的是實際呈現的前景與底色。
- [ ]  每個可按區域至少 **44 × 44 CSS 像素**；圖示按鈕亦符合。
- [ ]  在 **320 CSS 像素寬**下沒有頁面橫向溢出、重疊、截斷或被遮擋的操作。
- [ ]  只用鍵盤可完成全部主要流程；Tab 順序合理、焦點清晰可見、沒有焦點陷阱或被遮擋的焦點。
- [ ]  表單標籤、錯誤訊息、連結名稱、狀態提示及內容語意可理解；顏色不是唯一線索。
- [ ]  系統啟用減少動態效果時，非必要動效與平滑捲動已停用，介面仍可完整操作。
- [ ]  已在真實瀏覽器檢查主要畫面、主要互動、錯誤主控台及相關部機尺寸；未能測試的項目明確列為未驗證。
- [ ]  只改動任務授權的檔案；沒有更動其他既有工作、伺服器設定、內網資訊或登入資料。
- [ ]  設計變數全部用中文名，冇用英文變數名；冇用框架、冇用 CDN、冇用外部叫用。
- [ ]  冇用假掣、假連結、假字、假資料；冇清走 focus；冇做千篇一律嘅 AI 樣。

## 完成回報格式

完成收貨閘門後，以簡短清單交代：

1. 改了甚麼，以及涉及哪些檔案。
2. 實際通過的尺寸、鍵盤、對比及互動檢查。
3. 用咗邊啲設計變數（色、字、間距）。
4. 未能驗證的項目；沒有則明確寫「沒有」。
5. 收貨閘門結論：只有全部通過並有證據時才寫「通過」。

## 安全

- 抄任何外部 skill 之前，要先驗一次，睇下有冇外部叫用、要讀環境變數、要讀檔案以外嘅嘢。
- 唔好將外部 skill 嘅 code 原封不動咁抄，要抽概念，唔好抽 code。
- 唔好喺報告入面寫低完整地址、登入資料。
- 唔好改其他檔、唔好 commit、唔好 push，除非另外講明。
