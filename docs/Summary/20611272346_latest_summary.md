# 🛡️ TimeMem 專案開發日誌與資安教訓檢討 (2026-11-27)

## 1. 核心教訓與安全防護（Security First）
* **密碼 Hardcode 危機**：在嘗試自動化遠端 Docker 部署時，發現 `deploy_all.bat` 內部明文寫入伺服器帳號密碼。經緊急審查，確定該敏感腳本**尚未**推送上 GitHub（僅推送了 `sync_consensus.bat`）。
* **補救決策**：
  1. 立即終止自動化試錯循環，防止盲目遠端重啟遠端 Docker 造成不可預期嘅破壞。
  2. 決定事後手動更換伺服器密碼，並規劃長遠廢除密碼硬寫、改用 SSH Key 或環境變數嘅安全架構。

---

## 2. 自動化邊界與人工介入原則
* **工程邊界認知**：自動化腳本（如 `deploy_all.bat`）嘅職責應止於「本機 Push + 觸發遠端 Pull/Build」。當遠端 Docker daemon 發生崩潰或認證失效時，不應讓腳本在背景盲目自癒或亂改遠端設定，必須由人手登入伺服器（Joe-Server）進行狀態排查。

---

## 3. 下一步行動方針
1. **密碼重設**：手動更改 `joe-server` 嘅登入密碼。
2. **重構部署腳本**：移除腳本內嘅明文密碼，改為透過 Windows 環境變數或 SSH 密鑰（SSH Key）進行身分驗證。
3. **穩定部署驗證**：待伺服器 Docker 服務手動確認正常運作後，再恢復手動或安全自動化部署。
