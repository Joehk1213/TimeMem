# TimeMem PWA 前端規劃

## 目標與邊界

以暖紙色、安靜留白和緩慢有生命力的記憶背景，重整 TimeMem 的記錄／回顧入口；吸收 Joe 描述的 ASCII 鯊魚影片感覺，不複製其畫面或素材。實作仍須遵守新 SKILL：PWA 執行資產限於 `index.html`、`manifest.json`、`sw.js`、`icon.png`，不加套件、外部資源或建置流程。

Joe 已確認目前 Server 沒有記憶相片或時、人、地、事資料。本次只做前端殼和互動，不做後端或資料保存；中央輸入框可供打字和展示操作狀態，但內容不會保存。空資料時使用明確標成「示範」的示範內容呈現卡片、列表及背景變化，不可讓人誤以為是真實回憶或已成功保存。這是 Joe 對本次原型的明確決定；新 SKILL 原則上不允許假資料，因此實作時須把示範標示做得持續而醒目，並限定為本次示範殼，不可包裝成真實資料。

## 1. 現有殼的問題（只按已讀內容判斷）

- `index.html` 只有置中的單一輸入框和「M0 PWA Shell - 冇 Login / 冇資料」字樣；沒有產品問句、標題層級或下一步說明。最唔開胃之處是使用者不知道為何要輸入、輸入後會發生甚麼。
- 版面以整頁置中、最多 480px 的單一欄為主；作為測試殼可以，但沒有頂欄、內容層次、回顧入口或記憶列表，未能表達「記低與重溫」。
- 現有灰底 `#f5f5f5`、深灰字和普通邊框偏中性，沒有暖紙質感或品牌重點；字體只用系統字體，沒有標題、正文、輔助文字的字級層次。
- 輸入框有 `aria-label`，但沒有可見標籤、送出按鈕、表單結果或驗證流程；不能當作可用的記錄功能。
- 沒有卡片、按鈕、列表、空白／載入／錯誤狀態。現有說明是開發殼提示，不是面向使用者的空狀態。
- `manifest.json` 的主題／背景色仍是灰色。`sw.js` 目前快取殼檔，採先讀快取、找不到才取網絡；啟用時會刪除其他快取名稱。更新策略和快取清理範圍須在改版前核對。
- `icon.png` 只確認到 512×512、約 475 KB；本次無法視覺檢查圖案，因此不判斷它是否符合新方向，也不計劃改圖示。

## 2. 風格選擇與理由

**預設暖紙風＋輕、靜、留白的文字感。** TimeMem 是反覆記錄和回顧的工具，不是宣傳頁；暖白底與高可讀深色文字可讓人放心閱讀，克制的陶土色只提示主要操作。中央問句及輸入區要一眼可辨，背景照片只是低存在感的記憶氣息，不能妨礙讀字或按掣。

不使用重 3D、假光影、玻璃模糊、閃爍、漸層球體或大幅視差。動感由少量記憶照片／文字以很慢、很小的平移和縮放產生；前景保持穩定。對影片所述「順、靜、有生命力」的追求會以實機效能測試驗證，不預先宣稱所有裝置都能固定達到 60 FPS。

## 4. 版面結構與理由

1. **頂欄**：左側 TimeMem 名稱，旁邊固定顯示醒目的「示範」標記；右側只放有真實原型互動的入口。頂欄薄而穩定，讓人一入場就知道資料是示範。
2. **中央主區**：一句「而家諗緊咩？」作主要提示；下方放可見標籤的簡單輸入欄和清楚標示為示範操作的控制。輸入只在目前頁面記憶體中暫時展示，重新載入即消失，不寫入本機儲存或後端；介面明示「示範輸入不會保存」，不顯示虛假的保存成功。
3. **背景記憶層**：以少量示範項目展示時間、人、地、事、相片類型的變化；每項或每組均明確標示「示範內容」，頂欄仍常駐「示範」標記。相片尚不存在時用標明「示範圖片」的輕量佔位視覺，不冒充 Joe 的真實相片。項目疏落地分布於畫面外圍，避開中央文字、輸入框、頂欄和操作區。
4. **示範列表**：主區下方或「查看示範」展開的區域，以一行一筆呈現示範標題及時間，行間分隔；長文字自然換行。每筆標示「示範」，不使用真實使用者資料。
5. **示範回顧卡**：互動後以實色、可讀的浮層呈現示範圖片佔位、示範文字、時間與類別；卡片內保留「示範內容」標籤及明確關閉控制。長文和窄屏均可捲讀。
6. **操作控制**：主要送出按鈕靠近輸入欄；次要操作使用文字按鈕，不以小圖示取代名稱。所有可按範圍至少 44×44 CSS 像素。

## 5. 組件、狀態與實際動作

- **卡片**：顯示示範標題、類別、日期及示範圖片佔位；卡片內清楚標示「示範內容」。開啟時背景動效全部暫停以利閱讀。關閉卡片可回到原本畫面，焦點回到觸發項目。
- **背景相片／記憶項目**：以固定、有限組合的示範記錄輪替或隨機抽取，涵蓋時、人、地、事、相片佔位；「示範」標記不可因輪替或開卡而消失。桌面滑鼠移入某項時停止該項並開啟示範回顧卡；開卡後所有背景都暫停。滑鼠離開不應令卡片突然消失；由關閉控制收卡，再以連續、緩慢的狀態恢復原有漂移，不跳位。
- **觸控與鍵盤替代**：觸控點按記憶項目開卡，使用卡片內關閉控制收卡；鍵盤焦點到達項目後，以確認操作開卡，取消操作可關卡。不能把滑鼠懸停當成唯一入口。
- **背景動效**：少量元素各自錯開相位，以緩慢、低幅度的 `transform` 平移／縮放；不動畫版面位置或尺寸，不用閃爍、模糊、重陰影或逐格重繪。建議桌面最多 4 項、手機最多 2 項，依裝置實測再調整；背景層不得攔截中央區域的點按。啟用系統減少動態效果時停用循環位移及縮放。
- **按鈕**：示範控制提供可見的樣式狀態及即時前端回饋，例如開啟／關閉示範卡、切換示範列表。輸入旁的示範操作只更新頁面內暫態預覽並明示「示範，未保存」，不能宣稱寫入記憶。定義一般、滑過、按下、焦點、停用狀態；不設虛假的網絡處理中或保存成功狀態。
- **輸入框**：有可見標籤，允許打字以展示輸入及焦點狀態；提交或預覽只在當前頁面顯示，不保存、不呼叫後端、不進本機儲存，並清楚標示示範性。重新載入後還原預設示範畫面。
- **列表**：只列固定示範項目，每筆明示「示範內容」；控制項可切換或展開示範列，不聲稱是用戶的真實記錄。長列表原生捲動，不靠無限動畫。
- **空資料示範狀態**：以有清晰標籤的示範照片佔位、卡片和列表呈現不同視覺狀態；同時一直保留「示範」標記，避免把示範內容誤認為真實回憶。
- **載入狀態**：只示範前端狀態切換，不模擬真實網絡載入或保存；在所有示範狀態旁說明是介面示範。
- **錯誤狀態**：以明確標成示範的前端錯誤樣式展示錯誤排版及重試控制；重試只重設／重播示範狀態，不冒充真實資料操作。

## 6. 響應式與易用

- **320px**：單欄重排、容器可縮、長字換行；中央輸入和按鈕不受背景遮擋。背景至多保留一項低干擾記憶，若影響閱讀或操作便隱藏。
- **窄手機（至 599px）**：縮小外圍留白、照顧直向／橫向和系統安全區；觸控有直接開卡入口，不依賴滑過。
- **平板（600–899px）**：維持單一主任務欄，列表可增加可讀寬度；背景項目不超過兩項。
- **桌面（900px 起）**：主內容設合理最大寬度，列表可更寬，背景仍在外圍；不以滿版照片或裝飾填空。
- **對比及尺寸**：一般文字與背景對比至少 4.5:1，大字至少 3:1；按鈕與觸控操作至少 44×44 CSS 像素。焦點框須清楚，錯誤或成功不只靠顏色傳達。
- **鍵盤操作**：按「向前巡覽鍵」依閱讀次序移到下一項，按「反向巡覽鍵」返回上一項；以「確認鍵」啟動按鈕、連結和記憶項目；以「取消鍵」關閉回顧卡並把焦點交還觸發項目。所有功能不用滑鼠也可完成，焦點不得被卡片或固定區域困住、遮住。
- **減少動態效果**：尊重系統偏好；關閉非必要移動、縮放及平滑捲動，保留清楚的開卡、收卡和示範結果。觸控裝置減少背景項目及動效幅度。
