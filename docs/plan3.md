## 自我檢視：現有成品與參考片的差距

現有成品使用手寫字元漸層、身體橫截面和三角形魚鰭拼成魚形，再以隨機貝茲曲線移動整個水平魚身。雖然外框會移動、尾巴會擺，但魚身沒有跟隨游向轉動，沒有逐節脊椎彎曲；字元也只在簡化輪廓內排列，缺少參考片清楚的鯊魚身形和明暗塑形。因此呈現出來像一片字元波浪，不像真正游動的魚。

參考片連結的開源專案是 [stackedlol/ascii-sharks](https://github.com/stackedlol/ascii-sharks)，採用零執行期依賴的 Canvas ASCII 鯊魚引擎。其鯊魚形狀、鰭、20 節脊椎、轉向慣性、速度調整和逐格字元濃淡塑形，正是現有版本欠缺的部分。現有自製輪廓與路徑方案不再作為新版本基礎。

## 目標與邊界

- 只在現有暖紙風 PWA 背景呈現四條 ASCII 鯊魚；不生成小魚群、食物、海水網格、光點、熱度效果或游標水花。
- 使用開源引擎的鯊魚輪廓、魚鰭、脊椎波浪、轉向和速度模型；不再用手砌長字元網格或固定水平魚身。
- 保留暖紙底、頂欄、中央「而家諗緊咩？」、輸入框、記憶卡、列表、回顧卡及全部既有操作。
- 不接後端、不保存輸入、不改 Server 設定、不改 `manifest.json`、`sw.js`、`icon.png`；不 commit、不 push。
- 最終執行資產仍只有既有四個 PWA 檔案；引擎程式碼整合進單一 `index.html`，不加入 CDN、外載資源、套件或新執行檔。

## 實作方向

### 引擎移植

1. 以 `ascii-sharks` 的 MIT 授權原始碼為基礎，移植需要的 Canvas renderer、鯊魚 World 更新邏輯和數學工具至 `index.html` 內嵌 JavaScript。
2. 保留 MIT 授權要求：在內嵌程式碼附近附上原作者、版權聲明及完整 MIT 授權文字；不把原始碼移植描述成自行創作。
3. 建立四條 `classic` 鯊魚，採用引擎預設大小比例 `1、0.7、0.84、0.77`，保留不同初始位置、方向、相位及由引擎產生的個別游動差異。
4. 建立 World 時明確指定魚群數量為零；確認 renderer 不會畫出小魚、粒子、閃爍色點或背景網格。
5. 不將 TypeScript 模組或 `OceanEngine` 的外部 import 留在 PWA；交付時須能由單一 HTML 直接執行，無建置步驟及外部依賴。

### 外觀與 TimeMem 整合

- Canvas 保持透明並放在記憶背景最底層；畫布設為 `aria-hidden` 和 `pointer-events: none`。前景卡片、問句、輸入框、列表、按鈕及對話框維持原有層級和操作。
- 使用引擎的字元格取樣、鯊魚輪廓、鰭、眼、脊椎波浪及明暗密度塑形；將原本海洋用途的黑底、彩色點、閃色和裝飾效果關閉，改用克制的暖灰／暖棕字色配合現有暖紙底。
- 使用引擎的四條預設同種鯊魚比例，不另外畫四個手工輪廓；字元格密度足以辨認身體、頭、背鰭、胸鰭和尾部。
- 使用引擎自然轉向和跟隨脊椎，鯊魚隨游向轉身並由頭到尾彎曲，不以整條水平文字翻面代替轉向。
- 保留引擎的中心避讓與鯊魚間距；額外以實際前景矩形驗證，必要時只調整引擎的避讓力或畫布魚身尺寸，不移動、不改造前景介面。

### 暫停、恢復與減少動效

- 延用現有回顧卡開啟、游標停留記憶卡、分頁隱藏等暫停條件；暫停時停止動畫排程，不讓世界時間在背景繼續累積。
- 回顧卡關閉後，如果滑鼠仍停在觸發卡片，繼續暫停；游標離開才恢復。鍵盤開卡、按「Esc 鍵」關閉和焦點還原行為保持不變。
- 恢復時使用暫停前的鯊魚位置、脊椎、相位和速度，不重設到起點、不跳位。
- 系統設定「減少動態效果」時不啟動持續動畫；只顯示一個靜止、完整的鯊魚畫面，不閃爍、不漂移。

## 收貨閘門

- 只有四條可辨認的鯊魚；魚群數量為零；形狀和字元明暗由引擎 renderer 產生，不再使用目前的手寫長條網格。
- 魚身、魚鰭、頭尾比例、身體脊椎波浪、轉向和速度可從實際畫面辨認；四條魚不再整條固定水平朝向。
- 四條魚在畫面中各自自然轉向、上下左右游動；彼此不明顯重疊，並避開中央問句、輸入框和主要控制區。
- 暖紙底與既有 TimeMem 前景保持完整；魚不蓋住文字、卡片、列表、按鈕或焦點，不攔截任何點擊／觸控。
- 在 320 CSS 像素寬下無頁面橫向溢出；魚可縮放，但仍可辨認，且不遮擋必要操作。
- 開啟回顧卡、游標停留記憶卡及分頁隱藏時會停止；卡片關閉後須等游標離開才恢復；恢復不跳位。
- 啟用「減少動態效果」後只有靜止畫面，沒有持續動作或閃爍。
- JavaScript 語法、瀏覽器主控台、鍵盤開關卡和焦點還原均通過；無 CDN、無外部請求、無新增套件或執行檔。
- 實際 HTTP／安裝版及代表性裝置需檢查畫面與效能。未實機量測前不宣稱達到 60 FPS；未驗證項目須明確列出。
- 逐檔確認本次只有 `index.html` 改變，舊備份及本次新備份均完整存在。
