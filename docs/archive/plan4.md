# TimeMem PWA：四條 ASCII 鯊魚高還原度重整方案

本文件只作本次規劃。獲批後，開發在目前工作階段進行；不直接在運行中的 PWA 編輯。完成後先提供畫面與驗收證據；未獲額外部署批准前，不改運行中的 PWA。沒有 commit 或 push。

## 1. 現況與差距

已檢視目前運行版及 Joe 提供的公開參考短片。運行版已包含四條 `ascii-sharks` 鯊魚引擎、TimeMem 示範卡和輸入互動，但整體仍未達到目標：

- 暖紙色背景、較大的中央標題／說明和不透明記憶卡，把畫面切成一個傳統卡片式表單；參考感覺則是白色留白、中央小問句和簡單輸入層，魚成為畫面主要生命感。
- 魚雖由引擎生成，現有輸出仍偏淡、像稀疏字元碎片，鯊魚輪廓、背鰭、胸鰭、尾鰭和身體轉向不夠清楚。前次為效能減少的邊緣取樣應重新檢視，不應以犧牲魚形換取速度。
- 引擎目前的巡游行為偏向圍繞中央標題的固定巡弋；未充分呈現 Joe 要的四條魚各自游遍畫面、上下左右移動、沒有固定軌道的自然感。
- 記憶內容和卡片仍是前景主角，透明度不足；中央表單也沒有做到閒置時退為輕薄、需要輸入時清楚易用。

參考目標只取白色留白、ASCII 鯊魚外型與自然游動的視覺方法；不複製 Facebook 介面、商標、帳號、影片標題字幕或其他品牌素材。

## 2. 視覺方向與介面

- **底色**：改為乾淨中性白，不保留暖紙色，不加重漸層、假光影、玻璃模糊或閃爍。魚以黑灰階 ASCII 明暗塑形，避免彩色海洋特效。
- **中央輸入層**：縮小「而家諗緊咩？」和輔助文案，只保留一個清晰問句及簡單輸入控制，不再做大型 Hero 區或厚重表單卡。輸入內容仍不保存、不接後端，示範標籤及「輸入不會保存」說明保留。
- **閒置透明度（Joe 已選定）**：不使用時只令底板／邊框透明，問句、標籤、輸入框和按鈕仍清楚可見；聚焦／輸入時才顯示輕薄底板。絕不讓整組問句和控制項淡出或隱藏；實際焦點外框和文字對比仍須合格。
- **記憶卡**：改為無模糊的半透明白色卡面，卡片文字與控制項保持不透明。透明度以實際合成後仍符合文字對比為準；若背景魚影影響閱讀，先調整魚路徑，不以降低文字對比解決。
- **其他既有介面**：保留回顧卡、示範列表、空白／載入／錯誤示範狀態及其實際互動；以輕量透明樣式降低存在感，避免空狀態或錯誤資訊消失。所有新 CSS 自訂變數沿用中文命名。

## 3. 四條魚：保留引擎形體，重做不自然之處

- 保留已嵌入主頁並帶有 MIT 聲明的 `stackedlol/ascii-sharks` 引擎及四條 `classic` 鯊魚，零魚群；尺寸沿用目前 `1、0.7、0.84、0.77` 的差異起點。
- 保留引擎 20 節脊椎、魚身輪廓、眼／鰓、背鰭、胸鰭、尾鰭、頭尾朝向、速度慣性和逐節彎曲；不得再以手砌長字元網格、單行魚字、水平翻轉或整條魚剛體旋轉代替。
- 重新檢視並恢復原引擎的多點輪廓取樣與字元明暗塑形，讓頭、身、鰭和尾部形成連貫輪廓；只保留鯊魚本體，關閉魚群、黑色格線、彩色水點、尾流、閃色與裝飾粒子。採透明 Canvas 疊在白底，不讓 Canvas 蓋掉介面。
- 保留 MIT 授權全文及來源註記；不帶入 Facebook／發布者商標、字幕、按鈕或帳號資訊。

## 4. 游動、畫面佈局與前景避讓

- 以引擎的速度、轉向慣性及脊椎跟隨模型為核心；將固定中央橢圓巡航改成四條獨立的慢速漫遊。每條魚有不同大小、初始高度／方向、速度偏差及隨機相位，透過平滑而持續的方向變化自然游過上、下、左、右區域。
- 保留鯊魚彼此的柔性避讓與畫面邊界回轉；不使用固定長方形來回、同步掉頭、瞬間跳位或重複整齊圓軌。魚身會跟隨方向彎曲，尾段擺幅大於頭段。
- 以中央輸入區、頂欄控制、展開中的列表／狀態區和回顧卡作為動態避讓區。避讓使用柔性轉向，不讓魚直接穿過可讀文字或按鈕；必要時縮小背景魚及泳動範圍，不遮擋也不攔截操作。
- 背景 Canvas 固定在最底層並設為不接收指標事件；卡片、列表、問句、輸入框及控制項在其上方。魚不得改變版面尺寸或造成橫向捲動。
- 320px 手機寬度時保留四條魚，但按視窗縮放魚長及游動範圍；主輸入區優先，若安全區不足，魚沿畫面上下外圍游動，不穿越中央操作區。

## 5. 暫停、恢復與減少動效

- 保留目前的回顧卡開啟、滑鼠停留記憶卡及分頁隱藏時暫停背景動畫的行為；對話框關閉後，滑鼠仍停在觸發卡時繼續暫停，離開後才恢復。
- 暫停時保留四條魚位置、脊椎、速度和相位；恢復時沿用原狀態，不重播、不跳位。
- 系統設定「減少動態效果」時四條魚完全靜止，Canvas 不持續刷新；現有頁面互動仍可使用。
- 魚與背景不接收指標事件；魚不新增可點擊行為，也不影響回顧卡開關及焦點還原。

1. Joe 批准方案後，先在 Server 備份區建立全新日期資料夾，複製當時四個 PWA 檔案；保留所有既有備份，絕不覆蓋或清除。
2. 備份後逐一比對來源與備份的 SHA-256。若任一來源檔案已變更、複製雜湊不符、或主頁不是已檢視版本，立即停止，不覆寫任何檔案並回報 Joe。
3. 目前開發用的本機 PWA 主頁是舊殼，不可作為基底。通過備份核對後，才把當時運行版主頁複製到目前工作階段的暫存工作區開發；運行中的 PWA 不直接編輯。
4. 實作範圍只改 PWA `index.html`。不改 `manifest.json`、`sw.js`、`icon.png`、Server 設定、後端、資料保存、外部資源或其他專案程式。
5. 本階段只交付工作階段中的候選頁及驗收畫面，不部署。待 Joe 看過候選頁並另行批准部署後，才可部署唯一的 `index.html`；部署前後再次核對雜湊，任何不符即停止。
6. 不 commit、不 push。測試完成後只清理本次建立且路徑明確的暫存工作／測試資料，不碰新舊備份。

## 7. Grill-Me 迭代與收貨閘門

每次認為候選頁已完成時，按 `grill-me` 再問一次：「四條魚外型、身體波浪與方向轉身，是否真的接近參考？游動是否在四周自然變化而非固定軌道？整體留白、中央輸入層和透明記憶卡是否令魚成為主角？目前自評是否至少 95%？」只要任何一項答「否」或證據不足，就指出具體差距、修改並重新實測；不得以「已移植引擎」當成達標證據。

對照參考短片的相近畫面比例和多個魚身姿態，以五個 20 分項目自評，合計至少 95/100 才可進入最終驗收：魚形輪廓／字元塑形；身體波浪與尾鰭擺動；四魚各自轉向、速度及四方位游動；白底與精簡輸入構圖；透明卡片、閱讀操作及流暢度。任何單項低於 18/20 都要繼續修正。每次保存暫存截圖與測試結果作比較；95 分是有明確項目的自評門檻，不冒充客觀影像相似度，也不能取代 Joe 最後看候選頁確認。

- 正好四條引擎鯊魚、零魚群；魚身及尾部可辨認，魚鰭與轉向清楚，不是字元碎片或固定水平魚形。
- 四條魚速度、大小、高度和方向不一，分別上下左右漫遊；沒有同步移動、固定重複軌跡、互相重疊或突然跳位。
- 白底與參考感覺一致；中央問句小而簡潔，輸入只作單一前景入口；記憶卡透底但字仍清晰。背景魚不穿過可讀文字或阻擋按鈕。
- 回顧卡、滑鼠停留、頁面隱藏時暫停；離卡後平順恢復；系統減少動態效果時完全靜止。
- 320 CSS 像素寬無橫向溢出；所有操作可用鍵盤完成，焦點可見，按鈕可按範圍至少 44 × 44；實際文字對比符合一般文字 4.5:1。
- 檢查 JavaScript 語法、瀏覽器錯誤、網絡請求、記憶卡／列表／輸入互動及不同視窗尺寸；量測實機效能，不宣稱未測得的 60 FPS。
- 其他三個 PWA 檔雜湊不變；授權聲明完整；無外部依賴、服務設定變更、commit 或 push。
